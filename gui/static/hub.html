アーカイブ済み

アーカイブ（読み取り専用に）したモジュールです。アーカイブを解除すると再び変更でき、不要なら削除できます。

    設定

    すべてのモジュールに共通する設定と開発環境

    既定の所有者

    モジュールの作成・取得で所有者を指定しなかったときに使う、GitHubのユーザーまたは組織です。

    環境チェック

    まだチェックしていません。

      環境の準備

      Git が GitHub CLI の認証を使うように設定し、コミットの作成者（名前・メールアドレス）を設定します。

      このGUI

      GUIはバックグラウンドで動いています。ウィンドウをすべて閉じると、しばらくして自動で終了します。すぐに終了するには「GUIを終了」を押してください。

      ヘルプ

      ECOBuildの作業は、タスク（GitHubのIssue）ごとに進めます。GUIのボタンは、ecobuild のコマンドを実行しています。コマンドの名前を押すと、コマンド一覧の説明に移ります。

      1. 1

        モジュールを用意する

        ハブ › ＋ モジュール追加

        新しく作るか、GitHubから取得するか、手元のフォルダを登録します。

      2. 2

        タスクを作る

        モジュール › タスク管理 › ＋ 新しいタスク

        やることをタスク（Issue）にします。担当者・期限・見積もり・スプリントも付けられます。

      3. 3

        作業を開始する

        タスク管理 › タスク › 作業を開始

        タスクブランチ（task/番号）を作り、作業空間（このPCで作業する場所）を開きます。

      4. 4

        作って、確かめて、コミットする

        作業空間

        ファイルを編集し、ビルド・テストして、変更をコミットします。AIを起動して手伝わせることもできます。

      5. 5

        提出して、レビューを受ける

        作業空間 › 提出する

        確認（生成ファイル・ビルド・テスト）をしてから、作成元へ提出（PR）します。

      6. 6

        完了する

        作業空間 › 完了する

        提出を取り込み、タスクを閉じます。ほかの人の変更は同期で取り込みます。

      用語

      モジュール
      GitHubのリポジトリ1つ。制作・リンクの単位です。
      型
      モジュールの種類（C++・Python・汎用）。ビルドやファイルの扱いと、使えるコマンドが型で変わります。
      タスク
      GitHubのIssue。やることの単位です。
      タスクブランチ
      タスクの作業をするブランチ（task/番号）。変更はここでコミットし、提出で作成元に入ります。
      作業空間
      このPCでモジュールの作業をする場所（clone）。
      提出
      タスクブランチの変更を取り込んでもらうためのPR。レビューで承認されると完了できます。
      ビルド設定（プロファイル）
      名前を付けたビルドの設定（構成・並列数と、型ごとの項目）。

      ECOBuild / モジュール

      モジュールを追加

      追加方法

      ECOBuildで作成したモジュールをcloneし、依存先と生成ファイルを用意します。

      このフォルダの下にモジュール名のフォルダを作ります（親フォルダがなければ作ります）。

      詳細設定 説明・所有者・公開範囲

      既定は非公開です。GitHubのリポジトリ作成と初回のPushもまとめて行います。
